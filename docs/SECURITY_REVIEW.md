## 소스 회귀 검증 기록 — 2026-11-13

아래 테스트 수치는 해당 소스 검증 시점의 기록입니다. 현재 Pi 운영 연결 확인과 구분합니다.

- Node 24: 웹·서버·Pages 회귀 테스트 141개 통과
- Mac 설정·중계 복구 테스트 11개 통과
- 고정 Worker 경로·헤더·인증 전달 테스트 4개 통과
- 위 자동 테스트 총 156개 통과
- 전체 JS 구문 검사 통과
- 실행 시점의 npm audit --omit=dev: 알려진 취약점 0건
- 당시 디자인 확인은 예시 데이터 기준이고, 로그인 유지 변경은 자동 테스트와 실제 서버 API·DB로 검증했습니다. 당시 실브라우저 자동화에는 접근 제한이 있었습니다. 이후 실제 앱 내 브라우저 확인은 아래 운영 기록에 구분했습니다.

DB·Google API 응답은 자동 테스트에서 대역을 사용합니다. 사용자는 실제 학교 Google 로그인의 성공을 확인했고 운영 DB의 관리자 적용과 공개 API 연결을 확인했습니다. 실제 MySQL에서 갱신·재사용 차단을, 서버를 재시작한 뒤 HTTP 갱신 복구와 로그아웃 폐기를 확인했습니다. 브라우저 프로세스를 완전히 종료한 뒤의 재실행은 추가 확인 범위입니다. 알려진 취약점 검사 0건은 미발견 취약점이나 실환경 설정 오류까지 없음을 뜻하지 않습니다.

## 현재 Pi 운영 연결 확인 — 2026-11-13

고정 Worker API의 health가 `{"status":"ok"}`를 반환하고, VPC Service의 대상이 Pi의 loopback HTTP 3100 포트임을 확인했습니다. Pi 웹·MySQL의 약 9시간 가동 후 healthy 상태, `cloudflared 2026.11.0`의 QUIC 연결 4개와 밤사이 자동 재연결도 확인했습니다.

실제 앱 내 브라우저에서는 기존 학교 로그인 세션이 대시보드로 복구됐습니다. 공개 설정 버전 `485defb1c4f1`이 고정 Worker API를 사용하고 공개 HTML에 진단 UI가 없음을 확인했습니다. Pi 웹 컨테이너를 중지·시작하고 정식 터널 systemd 서비스를 재시작한 뒤 각각 healthy·active와 고정 Worker health HTTP 200을 확인했습니다. 그 뒤 실제 앱 내 브라우저에서 달력을 새로 불러와 수동 Google 재인증 없이 로그인과 과제 건수 표시가 복구됐습니다.

Pi에서 Google 공개 서명 인증서 조회가 HTTP 200과 키 2개를 반환했습니다. 이는 네트워크·인증서 조회 확인이며 새 Google 인증 흐름 전체를 증명하지 않습니다. 이전 Mac 컨테이너 두 개와 프로젝트 네트워크를 제거했고, 구형 감독·임시 중계 프로세스를 정확한 명령 식별 후 종료했습니다. 데이터와 백업은 보존합니다. Pi 전원 재부팅과 새 Google 인증 과정 전체는 아직 검증하지 않았습니다. [현재 운영 확인과 과거 검증 기록](VALIDATION.md)을 참고하세요.

## 운영자가 유지할 경계

- 관리자 이메일 목록에는 과제·사용자 관리 권한을 줄 운영자만 지정합니다.
- 학년·반은 사용자가 선택한 정보입니다. 별도의 관리자 승인이나 학적 확인은 하지 않습니다.
- GitHub Pages와 같은 Origin의 다른 프로젝트·저장소 편집자는 신뢰할 수 있어야 합니다.
- 서버·MySQL·비공개 첨부파일과 백업을 공개 디렉터리에 두지 않습니다.
- 현재 운영은 고정 Worker API와 Pi의 정식 터널을 사용합니다. Pi 전원·인터넷 또는 Cloudflare 경로 장애 시 서버 기능에 영향이 있습니다. 프로세스 상태와 내부·외부 health를 함께 확인합니다.
- 이전 Mac 중계는 현재 운영에서 실행하지 않습니다. 임시 중계 자동화가 Pages API 주소를 다시 바꾸지 않도록 구분합니다.

## 이전 Mac 접속 복구 기록 — 현재 Pi 운영에는 사용하지 않음

아래 내용은 임시 중계를 사용하던 이전 구성의 구현 기록입니다. 현재 운영 절차는 [Pi 안내](RASPBERRY_PI.md)를 따릅니다.

- 기본 도메인의 404와 프로젝트 URL `/assignment-alarm/`을 구분했습니다.
- 중단된 무료 중계는 재연결하고, 정상 응답·학교 Google 설정·정확한 CORS를 검증한 주소만 Pages에 배포하도록 했습니다.
- 실패한 공개 설정과 기존 오류 캐시는 재사용하지 않습니다. 로그인 화면에 수동 재시도를 제공합니다.
- API 주소가 바뀌면 runtime-config 파일 URL의 해시도 바뀌어 이전 연결 주소가 캐시에 남지 않습니다.
- 중계 프로세스는 자신이 실행했거나 소유자·실행 시작 정보·loopback 포트를 검증해 명시적으로 인계받은 중계만 관리합니다. SSH 개인키·에이전트·비밀번호를 사용하지 않으며, HTTPS API 주소만 GitHub에 전송합니다.

## 로그인 유지 보완

- 서버 메모리만 사용하던 세션에 MySQL 갱신 세션을 추가했습니다. 기존 사용자·과제·첨부파일은 수정하거나 초기화하지 않습니다.
- 90일 미사용 만료이며 사용할 때마다 연장합니다. 긴 접근 JWT를 영구 저장하지 않습니다. 갱신 자격은 사용할 때 교체하고 서버에는 해시만 저장합니다.
- 같은 갱신 요청의 짧은 재시도는 같은 결과를 반환하여 응답 유실에 대비합니다. 최근 256개 소비 이력을 보관해 재사용이 확인되면 해당 로그인 묶음을 폐기합니다. 더 오래된 소비 자격도 인증은 거절합니다. 이력과 사용자별 발급 빈도를 제한해 DB 사용량을 제한합니다. 임의의 잘못된 값으로 타인의 세션을 취소할 수 없게 검사합니다.
- Pages가 배포한 API Origin과 고정 인증 네임스페이스를 함께 확인합니다. 네임스페이스 자체가 임의 서버의 신원을 증명하는 비밀키는 아닙니다.
- 네트워크 장애는 로그인 만료로 처리하지 않습니다. 갱신·로그아웃의 동시 탭 처리를 검증합니다.

## 학생 관리자와 반 승인 제거

사용자 요청에 따라 반 승인 단계·대기 화면·승인 UI·서버 차단을 제거했습니다. 기존 DB의 class_approved 열은 데이터 보존과 이전 클라이언트 호환을 위해 남기되 접근 제어에는 사용하지 않습니다. 학교 로그인·반별 접근·본인 완료 상태 검사와 관리자 기능 권한 검사는 유지합니다. 학생 관리자 완료 자격은 서버의 검증된 학교 계정 형식과 현재 소속으로 판단하며 클라이언트가 보낸 플래그로 허용하지 않습니다.

## 즉시 반영·캐시·학생 공지

화면의 낙관적 변경은 API 권한을 대체하지 않습니다. 실패하면 해당 작업만 복원하고, 계정·소속·역할이 바뀐 뒤 도착한 응답은 버립니다. 최근 목록 캐시는 인증 상태와 계정·학년/반·역할·고정 인증 네임스페이스로 나누며, 로그아웃과 사용자 권한 변경 때 삭제합니다. 변경 요청을 시작한 뒤 도착한 과거 조회 결과는 캐시에 저장하지 않습니다. 캐시는 최대 20개·항목당 15만 문자·5분으로 제한합니다.

학생 공지의 대상은 서버 DB의 본인 학년·반으로 제한합니다. 사용자 삭제는 대상 행을 잠근 뒤 과제·공지·관련 제출 기록을 함께 삭제하며 중간 실패 시 전부 롤백합니다.

실제 MySQL 연결과 로컬 임시 HTTP 서버에서도 학생 공지 대상 제한·학생 관리자 본인 반 완료·교사/다른 반 거절·사용자/과제 연쇄 삭제를 확인했습니다. 검증은 하나의 외부 트랜잭션과 경로별 SAVEPOINT에서 실행했으며 전체 테스트 데이터를 롤백해 운영 자료에는 반영하지 않았습니다.

## 이전 Mac 중계 전환 구현 기록

이 절차는 현재 Pi 운영 경로가 아닙니다. 중계 복구 프로세스에 Cloudflare Quick Tunnel과 SSH 중계 간 전환을 추가했습니다. 각각의 제공자 호스트 형식을 제한하고, 실제 API의 health·CORS·클라이언트 ID·고정 인증 식별자를 검증한 뒤에만 새 주소를 배포합니다. 이전 연결의 늦은 실패가 새 연결을 중단하지 않도록 소유 프로세스와 주소도 재확인합니다.

## Pages 공개 설정 복구

오래 열린 로그인 화면의 연결 실패 시 같은 Pages 출처의 공개 JSON 설정만 새로 읽고, 고정 인증 식별자·HTTPS Origin·버전을 검증한 뒤 같은 로그인 문서를 한 번 갱신합니다. CSP를 즉석에서 넓히거나 갱신 토큰을 새 주소로 직접 보내지 않습니다. 과제 입력 화면에서는 자동 이동하지 않아 작성 내용을 보존합니다.

### 이전 SSH 중계의 주소 알림 호환

과거 Mac 중계에서는 SSH 제공자의 `run.localhost.tunnel.registered` 주소 알림 형식도 처리합니다. source의 정확한 SSH 호스트와 sessions 경로, subject/data 주소 일치, 허용 제공자 도메인을 모두 검사합니다. 이전 알림 형식도 유지하며 주소 회전을 새 연결로 배포합니다.
